# Testing and benchmarks

## Commands

```sh
cargo build
cargo test                                         # statistical tests run optimised (opt-level 3)
cargo test --release -- --include-ignored          # everything, with the long statistical runs
cargo clippy --all-targets -- -D warnings
cargo bench                                        # criterion: benches/{sign,keygen,e2e}.rs
python3 tools/gauss_tables.py --check              # src/tables.rs against its definition (mpmath)
```

`cargo test` runs 125 tests: 66 unit tests, 58 integration tests in 15 files, and 1 doctest.
Twelve more are ignored by default because they are long; `cargo test --release --
--include-ignored` runs all 137 in about 95 s on an Apple M4.

## What the tests cover

- **Parity with fn-dsa** at Falcon-1024's parameters (`tests/parity_fndsa*.rs`):
  - fn-dsa's signing known-answer test is reproduced byte for byte;
  - on 2048 messages (65,536 in an ignored run), fn-dsa's signer replayed around this crate's
    SampPre core gives the same signature and the same `s`, on fn-dsa's keys, on this crate's
    keys and at fn-dsa's toy degrees;
  - fn-dsa verifies preimages made with the public `samp_pre`.

  Output parity certifies every discrete decision and the constants (to about 10^-8 relative),
  not IEEE bit patterns. A unit test adds the bit level: the precomputed tree gives exactly the
  leaf centres and widths of fn-dsa's per-attempt recursion.
- **Known answers** (`tests/kat.rs`): TrapGen and SampPre at both presets.
- **Distribution:**
  - the coset Gaussian, enumerated exactly at toy size;
  - SamplerZ against the exact discrete Gaussian across the leaf widths;
  - the `f, g` sampler against `D_{Z,σ_fg}`;
  - a 200-bit replay of ffSampling;
  - the far-tail trial that fn-dsa's `BerExp` would accept.
- **Key generation** against Sage: NTRUSolve, the Gram–Schmidt norms and the whole candidate loop.
  The NTT check of `fG − gF = q` is tested against a big-integer oracle.
- **End to end and hardening** (`tests/pipeline.rs`, `tests/hardening.rs`):
  - `fG − gF = q` and `h f = g`, the norm bounds, the leaf range, SampPre's equation and norm
    bound, and the encodings, each re-checked by an independent computation;
  - the refusal of inconsistent trapdoors and invalid rings, and the leaf windows.

The statistical tools in [`examples/`](../examples) and the analysis scripts in
[`tools/stats/`](../tools/stats) reproduce the figures of [precision.md](precision.md). The Sage
fixtures are generated by `tools/keygen/fixtures.sage.py` and `tools/sign/precision_fixture.sage.py`,
with the exact NTRUSolve oracle of `tools/ntru_sizes.py`.

## Benchmarks

Measured on 2026-10-04 on an Apple M4 (4 performance and 6 efficiency cores, 16 GB), macOS
27.0.1, rustc 1.99.0, criterion 0.8.2, release profile, one thread unless stated. The laptop ran
other applications (1-minute load average 3.4-5.9). Medians of `benches/{sign,keygen,e2e}.rs`;
expect a few percent between runs.

| Operation | PCS | Falcon-1024 |
|---|---|---|
| TrapGen (fresh seed per iteration) | 5.87 ms | 4.10 ms |
| NTRUSolve, one solve | 4.57 ms | 2.61 ms |
| `ExpandedKey::new` for a generated or decoded key | 51.5 µs | 51.5 µs |
| `ExpandedKey::new` for a `from_parts` key (validation included) | 122 µs | 122 µs |
| SampPre, one call | 161 µs | 194 µs |
| SampPre throughput, 1 / 2 / 4 / 8 threads sharing one key | 6,180 / 12,030 / 19,420 / 25,370 calls/s | |
| Verify | 20.8 µs | 20.8 µs |
| `R_q` multiplication | 28.2 µs | 28.3 µs |
| `R_q` multiplication by a prepared operand / its preparation | 18.6 µs / 9.0 µs | |
| `R_q` inversion | 57.9 µs | 57.5 µs |
| invertibility test | 29.5 µs | |
| `SecretKey::validate` | 71.7 µs | |
| secret-key decoding, validation included | 76.5 µs | 75.7 µs |
| public-key decoding | 2.0 µs | 1.25 µs |
| fn-dsa 0.4.0 signing, for comparison | | 210 µs |

At the PCS set, SampPre spends about 115 µs on its 2048 leaf samples (about 56 ns each, of which
SHAKE256 output is about 18 ns) and the rest on the FFT, the tree and the lattice-point
arithmetic. TrapGen is dominated by NTRUSolve on resultants of about 9.6 kbit, with 20.2
candidates per key on average.

## Interoperability with fn-dsa

fn-dsa's verifying key stores `h` in its NTT representation, not in coefficient form.
`tests/e2e.rs` (`fndsa_vk`) converts this crate's `h` with fn-dsa-comm's `mqpoly_*` functions.

## Limitations of the testing

- Only aarch64 has been tested. On x86-64, fn-dsa runs other code paths, so the parity tests have
  not been run there.
- The MSRV, 1.95, has not been run itself: the code was checked with rustc 1.93.1 and tested with
  1.99.0.
